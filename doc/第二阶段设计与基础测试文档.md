## 2. 指令语义与编码

`vdot.vv vd, vs1, vs2`分别取两个128位向量源寄存器的低64位，按最低字节到最高字节解释为8个有符号int8元素，计算八项点积。结果以32位补码写入向量目的寄存器 `vd[31:0]`，`vd[127:32]`恒为0。源高64位不参与计算，不读取或累加旧目的。

合法配置固定为SEW=8、LMUL=m1、VL=8、vstart=0、vm=1。输出是单个标量数值，但目的仍为向量寄存器，不是整数rd。

```text
sum = Σ signed8(vs1[8*i+7:8*i]) × signed8(vs2[8*i+7:8*i]), i=0…7
vd = Cat(96'b0, signExtend32(sum))
```

采用项目自定义OP-V编码：funct6=111111、vm=1、funct3=000、opcode=0x57；match为 `0xfe000057`，mask为 `0xfe00707f`。例如 `vdot.vv v3,v1,v2` 的机器码是 `0xfe2081d7`。汇编宏通过 `.word`生成机器码，无需扩展GNU汇编器。

## 3. 数据通路与位宽

| 阶段 | 运算 | 寄存器 |
|---|---|---|
| S1 | 8路signed int8×int8并行乘法 | 8×16位products |
| S2 | 相邻乘积两两相加 | 4×17位sums2 |
| S3 | 相邻部分和相加 | 2×18位sums4 |
| S4 | 最终求和 | 1×19位sum8 |

```text
两个源低64位 → 8乘法 → S1 → 4加法 → S2 → 2加法 → S3 → 1加法 → S4
                                                               ↓
                                      19位和符号扩展到32位，再拼高96位零
```

各字节使用 `.asSInt`解释，加法使用 `+&`保留增长位。结果范围为−130048～131072；18位有符号数最大只能表示131071，因此最终和使用19位。输出格式化不增加第五级寄存器。FU输入到输出固定4核心周期，设计支持无阻塞启动间隔1周期。

## 4. 香山指令适配与控制

```text
编码识别 → 向量译码与配置检查 → m1单uop
        → 重命名、调度、读操作数 → VFEX0/VDot
        → 向量/V0写回 → ROB完成与提交
```

以下文件位于 `stage2/2.2_rtl/src/main/scala/xiangshan/`：

| 文件 | 适配职责 |
|---|---|
| [Instructions.scala](../stage2/2.2_rtl/src/main/scala/xiangshan/backend/decode/Instructions.scala) | 定义自定义BitPat编码 |
| [VecDecoder.scala](../stage2/2.2_rtl/src/main/scala/xiangshan/backend/decode/VecDecoder.scala) | OPIVV译码到FuType.vdot，向量写回，取消旧vd源依赖 |
| [DecodeUnit.scala](../stage2/2.2_rtl/src/main/scala/xiangshan/backend/decode/DecodeUnit.scala) | 检查vtype、SEW、LMUL和vstart，接入非法指令异常 |
| [FuType.scala](../stage2/2.2_rtl/src/main/scala/xiangshan/backend/fu/FuType.scala) | 在枚举末尾增加vdot，归类为向量整数运算 |
| [FuConfig.scala](../stage2/2.2_rtl/src/main/scala/xiangshan/backend/fu/FuConfig.scala) | 声明流水、固定4周期、128位结果、向量控制和写回能力 |
| [Parameters.scala](../stage2/2.2_rtl/src/main/scala/xiangshan/Parameters.scala) | 在VFEX0添加一套VdotCfg，沿用现有读写资源 |
| [VDotDataModule.scala](../stage2/2.2_rtl/src/main/scala/xiangshan/backend/fu/vector/VDotDataModule.scala) | 八路乘法、平衡加法树及四级寄存器 |
| [wrapper/VDot.scala](../stage2/2.2_rtl/src/main/scala/xiangshan/backend/fu/wrapper/VDot.scala) | 连接算术与共享控制流水，输出冲刷过滤及执行侧配置检查 |

包装器继承 `VecPipedFuncUnit`，算术各级使用对应 `regEnable`。ROB编号、物理目的pdest、写使能及向量配置与结果同步；输出当拍需要redirect取消的事务被屏蔽。实际VL等约束在输出端使用对齐控制检查。vm固定为1，无掩码计算；完整覆盖目的，不经普通向量尾部合并保留旧值。

接口保留旧vd和v0等兼容槽位，但它们不参与点积。设计复用已有调度、唤醒、固定延迟写回预约与提交机制，不新增寄存器文件或ROB。

## 5. 基础测试实例与检查方法

实际套件只有两个：`00_smoke`包含1个正数样本，`01_directed`包含10个定向样本；负数和边界分类共用后者的一次完整运行。

正数样本为 `[1,2,3,4,5,6,7,8]`与全1，点积36、低32位 `0x00000024`。定向套件的全部样本如下：

| 样本ID | 低8字节输入或检查目的 | 点积结果 | 低32位 |
|---|---|---:|---|
| 1 | 全0与全127 | 0 | `0x00000000` |
| 2 | 全1与全−1 | -8 | `0xfffffff8` |
| 3 | 全127与全127 | 129032 | `0x0001f808` |
| 4 | 全−128与全−128 | 131072 | `0x00020000` |
| 5 | 全−128与全127 | -130048 | `0xfffe0400` |
| 6 | [1,−2,3,−4,5,−6,7,−8]与全1 | -4 | `0xfffffffc` |
| 7 | 含−128、127、0、±1、±64的混合输入 | -40700 | `0xffff6104` |
| 20 | [0…7]与全2，源高64位为0 | 56 | `0x00000038` |
| 21 | 相同低8字节，源高64位为0xff | 56 | `0x00000038` |
| 22 | 相同低8字节，源高64位为0x80 | 56 | `0x00000038` |

ID20～22保持源低64位不变，仅改变高64位，结果均为56，证明高8字节不进入计算。所有样本都要求目的高96位为0，负数也不做128位符号扩展。

公共 [common.S](../stage2/2.3_tests/suites/00_smoke/source/common.S)首先检查 `vlenb=16`。程序以VL16装载完整源及预置为0xa5的旧目的，以VL8执行vdot，然后以VL16存储并逐字节比较完整16字节。这样能够发现低32位计算错误、高位未清零或误累加旧目的。

成功以a0=0结束；比较错误为1，VLEN错误为2，非预期异常为3。失败时a1记录样本ID，a2记录字节位置，a3/a4保存实际值和期望值。JSON中的expected是参考数据，实际检查在RTL执行的汇编程序中完成。

## 7. 局部RTL与流水验证

[VDotDecodeTest.scala](../stage2/2.2_rtl/src/test/scala/xiangshan/backend/fu/vector/VDotDecodeTest.scala)覆盖288种寄存器组合、唯一译码、单uop及非法配置；[VDotTest.scala](../stage2/2.2_rtl/src/test/scala/xiangshan/backend/fu/vector/VDotTest.scala)覆盖golden算术、标签、气泡、v0、逐级redirect及复位。2026-11-04两项测试均通过，实际检查1078笔输出，复跑后可在Mill终端输出中查看All tests passed。测试台输出ready保持为true。

## 8. 复现操作入口

完整依赖和基线准备见[stage2 README](../stage2/README.md)。已有对应vdot emu时，在新终端也应显式设置路径：

```bash
export PROJECT="$HOME/risc-v-compitition-26/cie2026-跳水-xiangshan-vdot"
export XS_ENV_ROOT="$(realpath "$PROJECT/../xs-env")"
export EMU="$XS_ENV_ROOT/XiangShan/build/emu"
cd "$PROJECT"
bash stage2/2.3_tests/run.sh 00_smoke
bash stage2/2.3_tests/run.sh 01_directed
# 可选：导出本次冒烟波形
WAVE=1 BEGIN=0 END=12000 bash stage2/2.3_tests/run.sh 00_smoke
```

`EMU`必须是包含本扩展的可执行文件；未设置时脚本会在启动前提示 `Set EMU...`，并未执行测试。源码接入由 `scripts/prepare-stage2.sh`完成，整核编译使用 `make emu CONFIG=KunminghuV2Config EMU_TRACE=1 -j30`。
