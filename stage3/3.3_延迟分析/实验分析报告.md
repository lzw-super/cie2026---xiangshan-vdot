# 第三阶段：实验与延迟加速分析报告

报告日期：2026-11-04。本阶段基于当前stage2的硬件设计：四级流水、单套vdot功能单元。

本报告对应第三阶段3.1.1～3.3提交要求。结论：NEMU扩展、真实协同仿真和标准RVV等价基线均已具备并验证；128次点积的完整程序实测为RVV 6378周期、vdot 4797周期，周期比 **1.3296×**，vdot总周期比baseline减少 **24.79%**。本次使用stage2新构建的emu与重新编译的NEMU参考库，完整执行15项DiffTest并重现了性能结果。

## 2. 3.1.1 NEMU扩展及3.1.2协同验证

NEMU新增精确译码与vdot执行helper，以独立C标量循环计算8项signed int8点积，读完源后再清空目的并写低32位，保证源/目的重叠安全。非法配置先抛异常，合法结束更新向量状态。参考库同时对齐启动ROM、NMIE复位值及本平台机器态VL非法路径的mtval选择，没有跳过vdot差分。

本轮重新构建并运行真实参考库，1100组合法和7种非法模型测试通过；全部15项整核DiffTest实际重新执行并通过。高位翻转负对照保留此前记录，本轮没有重新进行故障注入。

详见 [NEMU接入说明](../3.1.1_NEMU/接入说明.md) 与 [协同验证报告](../3.1.2_协同仿真/验证报告.md)。

## 3. 3.2 标准RVV组合基线

入口e8/m1/VL8，源v1/v2，v6为预先准备的完整零向量：

```asm
vmv1r.v    v3, v6
vwmul.vv   v4, v1, v2
vsetivli   zero, 8, e16, m2, tu, mu
vwredsum.vs v3, v4, v6
vsetivli   zero, 8, e8, m1, tu, mu
```

分别完成全目标清零、有符号8→16位乘法、配置16位乘积解释、16→32位宽化归约、恢复配置。归约目标的高位通过tu保留为零，完整128位结果与vdot一致。不能只比较低32位，也不能用可能溢出的16位普通归约代替宽化归约。

本基线每次调用恢复e8/m1/VL8并使用临时寄存器。42组等价性样本包括极值、零、混合符号和高位干扰；通过完整16字节自检及DiffTest。源码及构建方式见 [基线说明](../3.2_RVV基线/基线说明.md)。这是一种直接可执行基线，不宣称是所有批处理情形的最优RVV实现。

## 4. 测量口径与公平性

分别执行1、32、128次点积。两程序输入相同、初始化和最终检查相同，每轮都有相同的计数递减和分支；vdot主体1条，baseline主体5条。重复使用固定v1/v2，vdot之间没有读取上一轮结果的RAW链。计时来自RTL仿真器的 `cycleCnt`，包括启动ROM、加载、向量配置、循环、自检及退出。

报告主指标定义为：

`S = C_baseline / C_vdot`

周期减少比例定义为：

`R = (C_baseline - C_vdot) / C_baseline`

这里的latency是**测试程序端到端核心周期**。没有用主机wall time，没有用未经证明具有乱序串行化效果的rdcycle边界，也没有把完整程序周期除以次数冒充单条FU执行延迟。

## 5. 3.3 实测结果

|---:|---:|---:|---:|---:|---:|---:|---:|

| 32 | 267 | 395 | 4653 | 5034 | 381 | 1.0819× | 7.57% |

表格汇总2026-11-04实际运行统计。本提交不包含bench_*原始日志与镜像；运行run.py与report.py后，可在results/runs的新时间目录查看各项完整结果和性能表。

单次点积的公共启动与检查开销占很大比例，所以整程序收益接近1；重复次数增加后，baseline的多条运算、配置及依赖开销占比提高，加速比随之增大。实际周期比不是简单的5条指令除以1条指令：处理器会重叠执行，同时受到分支、调度和数据依赖等影响。

## 6. 算术延迟、RAW间隔和增量估计

本次冒烟VCD再次核对输入到输出为4周期；此前同一四级硬件设计的32条连续依赖测试相邻输入间隔为9周期。这两个数分别描述FU流水和整核依赖执行，不等于本报告RVV/vdot循环的总周期比。提交保留stage3/images中的实际截图，原始VCD不提交，可按stage3 README重新生成。

辅助增量估计：

- vdot：`(4797−4653)/(128−32)=1.5周期/点积`。
- baseline：`(6378−5034)/96=14周期/点积`。
- 增量成本比：`14/1.5=9.3333×`。

**9.3333×不是本报告主加速比，也不是单条指令延迟比。** 它基于两个长度不同程序的差分估计，仍含循环、配置、前端及布局影响，未直接分离纯运算窗口。vdot增量低于4周期并不矛盾：四级FU支持流水重叠，且当前循环无跨迭代点积结果依赖。



## 7. 结论与适用范围

在基于当前stage2四级流水设计的昆明湖V2上，vdot扩展通过真实NEMU差分及当前功能套件；标准RVV组合能实现相同完整结果。128次点积测试的端到端加速比为1.3296×，总周期减少24.79%，本轮复跑确认可复现。
