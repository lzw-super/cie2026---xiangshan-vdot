# 3.1.1 NEMU指令扩展

模型与当前stage2的RTL保持以下约定：编码match=`0xfe000057`、mask=`0xfe00707f`；e8/m1/VL8/vstart0/vm1；从vs1/vs2的低64位读取8个有符号int8，点积写入vd[31:0]，vd[127:32]全部清零，不累加旧vd。支持目的与源重叠及v0。

源码基于 [base-commit.txt](base-commit.txt)，补丁为 [vdot-nemu.patch](vdot-nemu.patch)，[source.sha256](source.sha256)覆盖实际快照。

| 文件（相对NEMU根目录） | 实现 |
|---|---|
| `src/isa/riscv64/include/isa-all-instr.h` | 注册vdot helper |
| `src/isa/riscv64/instr/rvv/decode.h` | 精确匹配OPIVV自定义编码 |
| `src/isa/riscv64/instr/rvv/vcompute.h` | 检查配置、signed点积、全128位写回 |
| `src/isa/riscv64/system/intr.c` | 对齐本平台机器态VL非法路径的mtval行为 |
| `configs/riscv64-xs-kmhv2-vdot-ref_defconfig` | 匹配昆明湖V2的NMIE复位状态 |

模型为独立顺序C循环：读取字节后显式将128～255减256转换为负数，用int32累加；在读完全部源之后才清空目的并写入低32位。这个顺序保证源/目的别名正确。正常结束清vstart并设置向量脏状态；非法参数先触发EX_II，不更新目的。

统一 [boot.bin](boot.bin) 传给DUT/REF，避免两版默认启动ROM不同。模型保持一般非法指令mtval策略，仅对本平台机器态vdot中“配置其余合法、VL不等于8”的后端异常路径对齐mtval=0；没有屏蔽CSR比较，也没有将vdot加入DiffTest skip。该异常适配不声称覆盖所有特权级。

复现参考库时，在匹配基线的NEMU仓库应用本补丁，执行 `make riscv64-xs-kmhv2-vdot-ref_defconfig`，再通过 `BUILD_DIR` 指定独立输出目录构建。参考配置为 [ref.config](ref.config)。本包只记录C功能语义，NEMU不模拟四级流水时序；延迟必须来自RTL。
